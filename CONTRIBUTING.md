## Before you start

Read [`docs/development/setup.md`](docs/development/setup.md) to get a working local environment,
then [`docs/architecture/overview.md`](docs/architecture/overview.md) to understand the
gateway/services/workers/libs shape of the system. Node `>=20.19.0` and `pnpm@9.15.9`
(see `packageManager` in `package.json`) are required — `pnpm install` enforces the pnpm version.

## Workflow

- All work lands on `main` via pull request. CI (`.github/workflows/ci.yml`) runs on every push and
  PR to `main`: dependency audit, `pnpm format:check`, `pnpm lint`, `pnpm swagger:validate`,
  `pnpm db:generate`, `pnpm build`, and `pnpm test:unit` (on PRs, scoped to packages affected by the
  diff via Turborepo's `--filter=...[HEAD^1]`).
- A local pre-push hook (`.husky/pre-push`) runs `pnpm contract:check` (OpenAPI lint) before every
  push — expect pushes to fail fast if the merged OpenAPI spec doesn't lint clean.
- Merging to `main` triggers CD (`cd.yml` → dev; `cd-staging.yml`, `cd-production*.yml` for the
  other environments) — see [`docs/operations/`](docs/operations/README.md).

## Before opening a PR

Run, in order:

```bash
pnpm format:check   # or pnpm format to auto-fix
pnpm lint
pnpm build
pnpm test:unit
pnpm swagger:validate
```

If you touched a Prisma schema file, also run `pnpm db:validate` and `pnpm db:migrate` to generate
a migration. If you touched a controller, run `pnpm openapi:export` so the merged OpenAPI spec
(`docs/api/openapi-merged.json`) stays current, and `pnpm docs:components` so the generated
component docs under `docs/components/` reflect the change.

See [`docs/development/testing.md`](docs/development/testing.md) and
[`docs/reference/commands.md`](docs/reference/commands.md) for the full picture — some test
commands (anything under `docker:e2e:*` / `test:system:docker`) are currently blocked because
`docker-compose.e2e.yml` doesn't exist in this repo; use `pnpm test:e2e` against a stack you start
yourself instead (`pnpm docker:up` or `pnpm dev`).

## Commit messages

The changelog (`CHANGELOG.md`, generated by `pnpm docs:changelog` /
`scripts/docs/generate-changelog.mjs`) is built from Git history and groups commits using
[Conventional Commits](https://www.conventionalcommits.org/) prefixes (`feat:`, `fix:`, `chore:`,
`docs:`, etc.). Use that format so your change shows up correctly.

## Adding to the monorepo

- New microservice → [`docs/development/adding-a-service.md`](docs/development/adding-a-service.md)
- New worker → [`docs/development/adding-a-worker.md`](docs/development/adding-a-worker.md)
- Changing existing endpoints/migrations/cross-cutting code →
  [`docs/development/modification-playbook.md`](docs/development/modification-playbook.md)

After adding a service, worker, or lib, run `pnpm docs:components` — it regenerates
`docs/components/{services,workers,libs}/*.md` from each package's own metadata
(`package.json`, `README.md` if present). Don't hand-write these files; fix the generator
(`scripts/docs/generate-component-docs.mjs`) or the package's own docs instead.

## Architecture boundaries

Do not casually restructure or relocate code under `libs/`, `services/*`, `workers/*`, `gateway/`,
`ws-gateway/`, `prisma/`, `seed/`, or `tests/` — these are the application's actual source
boundaries, not documentation structure, and are out of scope for documentation-only changes.
Structural changes here should go through the service/worker playbooks above and get explicit
review.

Before deleting or renaming any script, config file, or path, search the repo for callers
(`git grep` for the path/filename) — several Makefile targets and CI workflows reference scripts by
exact path.

## Secrets

Never commit real secrets, `.env` files with real values, or credentials. Only `.env.*.example`
template files (with placeholder values) belong in the repo. Real secrets for all environments are
managed in Infisical — see [`docs/operations/secrets-infisical.md`](docs/operations/secrets-infisical.md).
If you believe a secret has been committed, see [`SECURITY.md`](SECURITY.md).

## Documentation

- `docs/README.md` is the master index — start there.
- Component docs (`docs/components/**`) and `CHANGELOG.md` are generated — see
  [Adding to the monorepo](#adding-to-the-monorepo) above. Don't hand-edit generated sections.
- Everything else under `docs/` is hand-written; update the relevant file in the same PR as the
  code change it documents, not as a follow-up.
- If you're working from a sibling checkout of the frontend repo
  (`nestlancer-frontend`), some backend docs link to it with relative paths like
  `../../../nestlancer-frontend/docs/...` — this assumes both repos are cloned as siblings under
  the same parent directory.

## Known non-standard areas

Documented here rather than silently worked around, so nobody "fixes" them by accident:

- **`libs/tests`** has no `package.json` — it holds a standalone `jest.config.ts` whose
  `testMatch`/`collectCoverageFrom` patterns point at directories that don't exist, and no package
  imports from it. It is not a working library. See
  [`docs/components/libs/tests.md`](docs/components/libs/tests.md). Left in place rather than
  deleted because its removal/repair wasn't part of the 2026-10 documentation reset's scope — raise
  it with a maintainer before touching it.
- **`docker-compose.e2e.yml` does not exist**, even though `pnpm docker:e2e:*`,
  `pnpm test:system:docker`, and error messages throughout `tests/system/**` reference it. Creating
  this file (and a real Dockerized e2e lifecycle) is a real, open piece of work, not a
  documentation gap — see [`docs/reference/commands.md`](docs/reference/commands.md#known-broken--retired-commands).
- **`docs/api/sdk-reference.md`** contains a template placeholder support email
  (`security@yourdomain.com`) that was never filled in with a real address. Don't treat it as a
  real contact — see [`SECURITY.md`](SECURITY.md) for how to actually report something.
- **`.gitattributes`** references `docs/api/postman-collection.json`, which does not exist anywhere
  in this repo. Likely a stale reference to tooling that was removed or never added; flagged, not
  fabricated.
