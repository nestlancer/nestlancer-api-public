# Repository structure

### What's where, and why. Verified against the tree on 2026-10-03 — re-check before quoting counts elsewhere.

</div>

---

## Top level

```text
.
├── gateway/              API gateway (REST, auth guard composition, OpenAPI aggregation)
├── ws-gateway/           WebSocket gateway (Socket.IO)
├── services/             16 domain microservices (see table below)
├── workers/              10 queue consumers (see table below)
├── libs/                 28 shared packages consumed via "@nestlancer/<name>": "workspace:*"
├── prisma/               Single shared Prisma schema (split across prisma/schema/*.prisma),
│                         migrations, and raw SQL (check constraints)
├── seed/                 Python/shell seeding + demo-data tooling (its own lifecycle; not under scripts/)
├── scripts/              Repo-wide automation — see scripts/README.md for the full catalog
├── tests/                Cross-service system tests: tests/system/{smoke,e2e}
├── deploy/               K3s (Kustomize overlays) and Terraform
├── docker/               Dockerfiles (service-base, worker-base, gateway, ws-gateway,
│                         prod-monorepo) and the dev/prod Caddy proxy config
├── config/               Example monitoring config (Prometheus, Alertmanager, Promtail)
├── docs/                 This documentation tree
├── .github/workflows/    CI/CD (ci.yml, cd.yml, cd-staging.yml, cd-production*.yml, build-images*.yml)
├── .cursor/rules/        Cursor IDE rules (11 .mdc files) — not documentation, don't delete
└── .husky/               Git hooks (pre-push)
```

Workspace packages are declared in `pnpm-workspace.yaml`: `services/*`, `workers/*`, `libs/*`,
`gateway`, `ws-gateway`.

## Services (16)

`admin`, `auth`, `blog`, `contact`, `health`, `media`, `messaging`, `notifications`, `payments`,
`portfolio`, `progress`, `projects`, `quotes`, `requests`, `users`, `webhooks`.

Each has its own `package.json`, `src/`, `tests/`, and (all 16) a package-local `README.md`. See
[`docs/components/services/`](../components/services/) for one doc per service.

## Workers (10)

`analytics-worker`, `audit-worker`, `cdn-worker`, `document-worker`, `email-worker`,
`export-worker`, `media-worker`, `notification-worker`, `outbox-poller`, `webhook-worker`.

8 of the 10 have a package-local `README.md` (`document-worker` and `export-worker` do not — not
yet added as of 2026-10-03). See [`docs/components/workers/`](../components/workers/) for one doc
per worker (all 10 are covered there regardless).

## Libraries (28)

`alerts`, `audit`, `auth-lib`, `cache`, `circuit-breaker`, `common`, `config`, `crypto`, `database`,
`documents`, `email`, `health-lib`, `idempotency`, `logger`, `mail`, `metrics`, `middleware`,
`notifications`, `outbox`, `pdf`, `queue`, `search`, `storage`, `testing`, `tests`, `tracing`,
`turnstile`, `websocket`.

See [`docs/components/libs/`](../components/libs/) for one doc per library.

> **Known anomaly — `libs/tests`:** unlike the other 27 libraries, `libs/tests/` has no
> `package.json` or `src/` — only a `jest.config.ts` whose `testMatch`/`collectCoverageFrom`
> patterns point at directories that don't exist. No other package imports from it. It is not a
> working package today. See [`docs/components/libs/tests.md`](../components/libs/tests.md) for
> detail. Left in place (not deleted) pending a maintainer decision — see
> [`CONTRIBUTING.md`](../../CONTRIBUTING.md#known-non-standard-areas).

## Images (28 production images)

1 gateway + 1 ws-gateway + 16 services + 10 workers. The canonical list — ports, Dockerfile paths,
Compose service names, and per-environment config — lives in
[`scripts/docker/workloads.manifest.json`](../../scripts/docker/workloads.manifest.json), **not**
in this document. `docker-compose.prod.yml` and the K3s manifests under `deploy/k3s/base/workloads/`
are both generated from that manifest — edit it, not the generated output.

## Compose files that exist vs. are referenced-but-missing

| File | Status |
| :-- | :-- |
| `docker-compose.dev.yml` | Exists — full app-tier dev stack (watch mode), external infra via Tailscale |
| `docker-compose.local.yml` | Exists — Caddy dev reverse-proxy overlay only |
| `docker-compose.prod.yml` | Exists — generated by `pnpm docker:prod:generate` |
| `docker-compose.prod.proxy.yml` | Exists — production Caddy proxy |
| `docker-compose.prod.node-exporter.yml` | Exists — optional Prometheus node-exporter sidecar |
| `docker-compose.e2e.yml` | **Missing** — referenced by `pnpm docker:e2e:*` / `test:system:docker` / `test:e2e:docker`. Never added to this repo. |
| `docker-compose.yml` (plain) | **Does not exist** — some `Makefile` targets referenced it historically; fixed/retired during the 2026-10 reset, see [`CONTRIBUTING.md`](../../CONTRIBUTING.md#known-non-standard-areas) |
| `docker-compose.test.yml` | **Does not exist** — same as above |

## Documentation tree

```text
docs/
├── README.md            Master index — start here
├── architecture/        System design: overview, data flow, DB schema, events, queues, WebSockets
├── api/                 API standards, OpenAPI mirror, per-service endpoint specs
├── components/          One doc per gateway/service/worker/library
├── development/         Setup, local workflow, testing, coding standards, troubleshooting
├── operations/          Deployment (dev/prod/VPS/K3s), database, secrets, runbooks/
├── reference/           This file, commands.md, environment-variables.md, feature-inventory.md
├── decisions/           Architecture decision records (formerly docs/adr/)
├── changelog/           Generated CHANGELOG.md mirror + migration notes
└── seeding/             Demo/seed data flow documentation
```

## Root standard files

`README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `LICENSE`. Plus two files specific
to this public mirror distribution (not product docs — see
[`docs/README.md`](../README.md#about-this-public-mirror)): `SANITIZATION_MANIFEST.md` and
`OVERALL_REPORT_REMOVED.md`.
