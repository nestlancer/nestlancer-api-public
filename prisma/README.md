## 📂 Project Structure

- `schema/`: Modular Prisma schema files. The main entry point is `schema.prisma`.
- `migrations/`: SQL migration files generated by Prisma.
- `prisma.config.ts`: Prisma configuration using the `earlyAccess` multi-file schema feature.

Seeding is `bash seed/seed.sh`. See [`seed/README.md`](../seed/README.md).

## 🛠 Development Commands

All database commands should be run from the root directory using `pnpm`.

> [!IMPORTANT]
> **Node Version Requirement**: This project requires **Node >= 20.19.0** for Prisma tooling. If your system node is older (e.g., v20.10.0), commands like `pnpm db:generate` may fail with `ERR_REQUIRE_ESM`. Use the `npx` workarounds below if you cannot upgrade your Node version.

### 1. Schema Management

- **Generate Prisma Client**: Updates the Prisma Client after schema changes.
  ```bash
  # Ensure DATABASE_URL is in the environment
  export DATABASE_URL=$(grep DATABASE_URL .env.development | cut -d '=' -f2-) && pnpm db:generate
  ```
- **Create & Apply Migration**: Use this when you change any `.prisma` file in `prisma/schema/`.
  ```bash
  export DATABASE_URL=$(grep DATABASE_URL .env.development | cut -d '=' -f2-) && pnpm db:migrate
  ```

### 2. Seeding & Reset

- **Seed Database**: Runs `bash seed/seed.sh --env=dev --phase=core,content`. To run one phase, or to seed production without wiping it, follow [`seed/README.md`](../seed/README.md).
  ```bash
  pnpm db:seed
  ```
- **Reset Database**: Drops the database, replays migrations, then runs `seed/seed.sh` for core and content. The API stack must be up. **Caution: Destructive!**
  ```bash
  pnpm db:reset
  ```

### 3. Visualization

- **Prisma Studio**: Opens a GUI to explore and edit your database data.
  ```bash
  pnpm db:studio
  ```

## 🚀 Applying migrations

Migrations use **`MIGRATION_DATABASE_URL`** (`nl_platform_migrate` — DDL). Runtime and Prisma Client use **`DATABASE_URL`** (`nl_platform_app` — DML).

**GitHub CD (dev VPS)** runs `scripts/db/migrate-deploy-ci.sh` before `docker compose up`. K3s production deploys should run the same script (or a Kubernetes Job) before routing traffic.

For local/emergency use:

| Command                                          | When to use                                                         |
| :----------------------------------------------- | :------------------------------------------------------------------ |
| `pnpm db:migrate`                                | Local dev: create migration SQL from schema changes                 |
| `pnpm db:migrate:status`                         | Check pending vs applied migrations (uses `MIGRATION_DATABASE_URL`) |
| `pnpm db:migrate:deploy`                         | Apply pending migrations (VPS, staging, prod)                       |
| `pnpm db:migrate:deploy:manual`                  | Same as deploy, with confirmation prompt (recommended on VPS)       |
| `pnpm db:migrate:bootstrap`                      | Init flow: generate client + regen SQL if missing + deploy          |
| `bash seed/seed.sh --env=dev --phase=core,content --migrate` | First-time schema + seed |

On the **VPS** (must reach DB over Tailscale):

```bash
cd /root/nestlancer-backend-api
git pull origin main
# .env.infisical must include MIGRATION_DATABASE_URL (add manually in Infisical — not in app runtime container)
./scripts/db/migrate-deploy.sh
```

Avoid `migrate dev` on shared servers. Use `migrate deploy` only.

- **New empty environment** (first-time DB): `bash seed/seed.sh --env=dev --phase=core,content --migrate`

## 🧭 E2E Database Runbook (Important)

Use this when `.env.e2e` is used and you need to rebuild migrations, migrate, and seed from scratch.

### Why this exists

E2E DB setup can fail if:

- migration files were deleted/regenerated,
- database is not schema-empty (`P3005`),
- Prisma migration is marked failed (`P3018`),
- DB user lacks shadow DB permission (`P3014`) for `migrate dev`.

### Prerequisites

- Use Node `>= 20.19.0` (project minimum for Prisma tooling in this repo).
- Prefer explicit env var export over `source .env.e2e` (that file has decorative lines/comments that are not shell-safe).

```bash
export DATABASE_URL='postgresql://USER:PASSWORD@REDACTED_E2E_HOST:5434/nl_platform_e2e'
```

### Standard E2E flow (fresh migration + migrate + seed)

1. Generate Prisma client:

```bash
npx -y node@20.19.0 ./node_modules/prisma/build/index.js generate
```

2. Create a new migration SQL from current schema (when previous migration SQL is missing/invalid):

```bash
ts=$(date +%Y%m%d%H%M%S)
mkdir -p "prisma/migrations/${ts}_init"
npx -y node@20.19.0 ./node_modules/prisma/build/index.js migrate diff \
  --from-empty \
  --to-schema prisma/schema \
  --script \
  --output "prisma/migrations/${ts}_init/migration.sql"
```

3. If deploy fails with `P3005` (schema not empty), reset schema with admin user:

```bash
PGPASSWORD='REDACTED_E2E_PASSWORD' psql -h REDACTED_E2E_HOST -p 5434 -U nl_infra_admin -d nl_platform_e2e \
  -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public; GRANT ALL ON SCHEMA public TO nl_platform_app; GRANT ALL ON SCHEMA public TO nl_infra_admin;"
```

4. Ensure DB-level privileges for app user (if `permission denied for database` appears):

```bash
PGPASSWORD='REDACTED_E2E_PASSWORD' psql -h REDACTED_E2E_HOST -p 5434 -U nl_infra_admin -d postgres \
  -c "GRANT CONNECT, CREATE, TEMPORARY ON DATABASE nl_platform_e2e TO nl_platform_app;"
PGPASSWORD='REDACTED_E2E_PASSWORD' psql -h REDACTED_E2E_HOST -p 5434 -U nl_infra_admin -d nl_platform_e2e \
  -c "GRANT USAGE, CREATE ON SCHEMA public TO nl_platform_app; ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO nl_platform_app; ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO nl_platform_app;"
```

5. If needed, clear failed migration state (`P3018`) before re-deploy:

```bash
npx -y node@20.19.0 ./node_modules/prisma/build/index.js migrate resolve --rolled-back <migration_folder_name>
```

6. Apply migration and seed:

```bash
npx -y node@20.19.0 ./node_modules/prisma/build/index.js migrate deploy
bash seed/seed.sh --env=dev --phase=core,content --skip-export
```

### `migrate dev` note (`P3014`)

`migrate dev` creates a shadow database. If role does not have `CREATEDB`, it fails with `P3014`.

Options:

- Temporarily grant/revoke `CREATEDB` for e2e role.
- Or use `SHADOW_DATABASE_URL` with an admin-capable role.
- Or skip `migrate dev` and use `migrate diff --from-empty ... --output ...` + `migrate deploy` (the flow above).

## 🔑 Environment Variables

### Runtime (app / seeding)

- `DATABASE_URL`: Main connection string — `nl_platform_app` (DML only)
- `DATABASE_READ_URL`: (Optional) Read replica — `nl_analytics_readonly`

### Migrations / init only (not in app runtime container)

- `MIGRATION_DATABASE_URL`: Prisma migrate deploy — `nl_platform_migrate` (DDL). Required in `.env.infisical` for `INIT_MIGRATE=1`, `pnpm db:migrate:deploy`, and migrate scripts. **Add manually in Infisical** — do not inject into Next.js/NestJS runtime containers.

### Seeding

- `ADMIN_EMAIL`, `ADMIN_PASSWORD`: Admin account. Password defaults to `REDACTED_DEMO_PASSWORD` when unset.
- `ADMIN_FIRST_NAME`, `ADMIN_LAST_NAME`: (Optional) Admin display name.

### Loading Environment Variables

Since `prisma.config.ts` requires these variables explicitly, you can load them before running any `pnpm db:*` command:

```bash
export $(grep -v '^#' .env.development | xargs) && pnpm db:generate
```

Alternatively, ensures a `.env` file exists (symlink is created by the system):

```bash
# Check if .env exists
ls -la .env
```

### 4. Version-Safe Workarounds (Recommended)

If you encounter Node version issues or ESM errors, use these explicit commands:

- **Generate Client**:
  ```bash
  export DATABASE_URL=$(grep DATABASE_URL .env.development | cut -d '=' -f2-) && npx -y node@20.19.0 ./node_modules/prisma/build/index.js generate
  ```
- **Apply Migrations**:
  ```bash
  export DATABASE_URL=$(grep DATABASE_URL .env.development | cut -d '=' -f2-) && npx -y node@20.19.0 ./node_modules/prisma/build/index.js migrate deploy
  ```
- **Seed Database**:
  ```bash
  export DATABASE_URL=$(grep DATABASE_URL .env.development | cut -d '=' -f2-) && bash seed/seed.sh --env=dev --phase=core,content --skip-export
  ```
